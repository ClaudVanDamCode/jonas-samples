WordPress (Elementor) to Next.js on Vercel: keeping the rankings

How the SEO side of the move is run, what the developer gets as written requirements, and a working tool from the toolkit: a redirect-map checker that finds chains, loops, gaps and risky rules, then writes the next.config.js and vercel.json redirects. Everything runs in this page; nothing you paste leaves your browser.

The approach, in five steps

Advisory and QA only: the developer builds, this work makes sure nothing that ranks today gets lost on the way.

Step 1

Inventory

  • Full crawl of the live site: every URL, status, title, meta description, canonical, H1, robots, schema types
  • XML sitemaps and Search Console pages export merged in, so pages with traffic but no internal links are not missed
  • Top pages by clicks and backlinks flagged as "must keep"
Step 2

Risk review

  • WordPress URL patterns: categories, tags, pagination, feeds, ?p= IDs, attachment pages, uploads
  • Trailing slash and case rules
  • Rendering: content must be in the server HTML, not filled in later by the browser
Step 3

Requirements

  • One written sheet for the developer (below)
  • A redirect map, old URL to final new URL, checked with the tool on this page
  • Metadata and schema mapped per template
Step 4

Staging QA

  • Crawl the staging build and compare with the inventory, page for page
  • Every old URL tested against the redirects: one hop, 301/308, ends on a 200
  • Preview builds kept out of the index
Step 5

Launch and after

  • Same checks on the live domain within hours of the switch
  • New sitemap submitted, Search Console coverage and 404s watched
  • Short report: what was checked, what was fixed, what to watch

Requirements sheet for the developer (excerpt)

What the developer receives, written so each line can be ticked off and tested on staging.

URLs and redirects

Every old URL that returned 200 either keeps its path or has one 301/308 rule straight to its final new URL. No chains, no loops, no blanket redirect of old pages to the home page. One trailing-slash rule for the whole site, set in next.config.js.

Status codes

Removed pages with no equivalent return a real 404 (or 410), not a 200 "not found" page. The 404 page itself returns status 404.

Titles and descriptions

Each template sets title and meta description through generateMetadata (or the page's metadata export), carried over from the current site for every "must keep" page.

Canonical tags

Absolute, self-referencing canonical on every indexable page, on the production domain, never the *.vercel.app address.

Indexing controls

Preview and staging builds send noindex; production does not. robots.txt and sitemap.xml generated (for example app/robots.ts and app/sitemap.ts) and listing only final 200 URLs.

Rendering

Main content, links and headings are in the HTML the server sends (static or server rendering), so search engines see them without running scripts.

Structured data

JSON-LD that the SEO plugin wrote today (Organization, Article, Breadcrumb, FAQ, Product) is rebuilt per template and passes the Rich Results test.

Images and media

Files under /wp-content/uploads/ that have traffic or backlinks are redirected or kept. Alt texts carried over; next/image with set sizes to protect layout stability.

Internal links

Menus, body links and breadcrumbs point straight at the final URLs, not at addresses that redirect.

Speed

Core Web Vitals on the main templates measured on staging and kept at or better than today: LCP, INP and CLS.

What you get
